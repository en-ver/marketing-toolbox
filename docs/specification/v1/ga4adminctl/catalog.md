# `ga4adminctl` v1 — complete GA4 Admin API catalog

## Contract status and authority

This is the complete contract-first public catalog for the Google Analytics Admin API **v1beta** surface in `google-analytics-admin==0.30.1`. It is documentation only: it defines no CLI implementation, service adapter, credential loading, or live call. `../upstream-inventory.json` is the method-by-method authority; the binding eligibility rules are in [requirements.md](../requirements.md). Google calls the upstream surface v1beta; every target below is therefore `stable-target` in this project, **not** a claim that Google has made it GA.

- **Coverage:** 50 non-deprecated v1beta REST operation targets; 49 generated Python callables because the account and property access-report routes deliberately share `AnalyticsAdminServiceClient.run_access_report`.
- **SDK:** `google.analytics.admin_v1beta.services.analytics_admin_service.AnalyticsAdminServiceClient`; callable names below were verified against the pinned SDK. No hand-written HTTP client is permitted.
- **Response:** stdout is one `marketing-tools/v1` JSON success envelope (`schemaVersion`, `command`, and `data`). For live reads and applies, `data` is the official response converted with protobuf JSON mapping (camelCase field names; no semantic remapping and no pagination aggregation); `google.protobuf.Empty` becomes `{}`. Diagnostics are redacted and go to stderr only.
- **Lifecycle:** all rows are upstream `v1beta`, non-deprecated in the inventory snapshot, and project `stable-target`. Recheck inventory deprecation metadata whenever the SDK changes.
- **Local descriptor tool:** `ga4adminctl sdk schema` is a local-only SDK descriptor reader, not an Admin API operation; see [the SDK-backed introspection specification](../sdk-backed-introspection.md).

## Public prerequisites and common execution rules

- Provide a service-account credential through `GOOGLE_SERVICE_ACCOUNT_JSON` or `GOOGLE_APPLICATION_CREDENTIALS` before a live command. The caller must have GA access appropriate to the resource; `analytics.readonly` is chosen whenever the method permits it, otherwise `analytics.edit` is required. A successful credential grant does not confer account/property permission.
- Resource identifiers are canonical, case-sensitive names and must match the row regex exactly. The CLI neither discovers a parent nor accepts a bare numeric identifier where the route requires a resource name.
- All JSON bodies use `--body <file|->` and must be one JSON object. The pinned official Google Admin SDK protobuf JSON parser is the structural authority: it rejects unknown fields and invalid JSON field types. The CLI injects route flags into the SDK request and rejects duplicate route fields. `--update-mask` is required where listed, is a nonempty comma-separated subset of mutable body fields, and cannot name route/output-only fields.
- Paged commands accept only the shown `--page-size` and `--page-token` (and other shown query flags). `--page-size` is an integer from 1 through 200 (default 50); when supplied, `--page-token` is a nonempty opaque token passed unchanged; and `--show-deleted` is a boolean. `properties list --filter` accepts only `parent:accounts/<numeric-id>`, `ancestor:accounts/<numeric-id>`, or `firebase_project:projects/<project-id>` (a 6–30-character project ID beginning and ending with an alphanumeric character). Paged commands return **one raw page** and never iterate a pager or follow `nextPageToken`. Pass the returned token in a new invocation.
- `read` commands make no state change. Each `mutation` or `sensitive action` requires exactly one of `--dry-run` or `--apply`; dry-run validates without credentials or a network call and writes its request plan in the success envelope's `data` field. `sensitive read` and `sensitive action` additionally require `--acknowledge-sensitive-data` before a response/request that can expose secrets, access/audit data, or user-data controls is emitted or dispatched. Do not log bodies or responses containing secret material.
- All commands use exactly one SDK dispatch with `retry=None`; no public Admin command automatically retries. Mutations and sensitive actions have no idempotency key; a timeout after dispatch is an unknown outcome and must be reconciled by a read before any manual retry. The same no-retry rule applies to reads so callers retain control over retries and quota use.
- Minimum tests for every row: command/help discovery; route/query/body boundary validation; fake SDK request and protobuf-JSON response fixture; normalized/redacted error and exit-code case; SDK-adapter callable assertion; and a separately approved, bounded live read-only smoke test where access permits. Every mutation/sensitive action also needs dry-run, missing-`--apply`, and (when classified sensitive) missing-acknowledgement refusal tests. Live mutations require separate authorization and a disposable target.

## v1alpha Audience exception — excluded from public v1

The prior idea of exposing `ga4adminctl audiences create` from Admin API v1alpha is **not** an exception to this catalog and is excluded from public v1. The v1alpha Audience API can be changed or shut down independently; it has no v1beta Audience counterpart in the pinned SDK. It therefore has no stable CLI path, SDK adapter, fixture, or help entry. A future preview-only contract would require separate versioning and explicit approval under [requirements.md](../requirements.md); it cannot be introduced silently.

## Implementation order

Implement in safety and dependency order, one reviewed command family at a time:

1. Read-only discovery: account summaries, account/property get/list, data-sharing/data-retention gets, and all non-secret list/get operations.
2. Sensitive read boundaries: account/property access reports, change history, and measurement-protocol-secret get/list, including acknowledgement/redaction tests.
3. Ordinary mutable resources: property/account updates, custom dimensions/metrics, data streams, Firebase/Google Ads links, and key events, with dry-run/apply contracts.
4. Sensitive and irreversible work: secret writes/deletes, account/property deletion, provisioning ticket, and user-data acknowledgement, only after disposable-target acceptance fixtures exist.

Before implementation, promote each matrix row into focused command/fixture coverage without changing its public path, SDK mapping, safety classification, raw-page rule, or response mapping.
